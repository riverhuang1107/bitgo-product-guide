enigmhaven VPS API

Use bitgo for enigmhaven VPS

In addition to model-token consumption, bitgo brings VPS creation, queries, start, stop, and deletion into the same auditable payment-authorization chain. This guide covers every API for VPS resources, SSH keys, and VPS instances.

Only GET /vps/v1/resources is unsigned. Every other API reuses the Model Inference API's two-layer authentication: wallet business signing plus interface-level ECDSA signing.

VPS Resources API

Query available resources first to obtain the zoneId, instanceTypeId, and imageId required when you create an instance. This is the only VPS endpoint that does not require wallet authorization or an interface-level ECDSA signature.

ItemValueDescription
Endpointhttps://api-bitgo.enigmhaven.com/vps/v1/resourcesLists available zones, instance types, and images
MethodGETNo authentication headers
Content-Type—No request body

Example

curl "https://api-bitgo.enigmhaven.com/vps/v1/resources"

Response structure

zones[zoneId]
├── zone
└── instanceTypes[instanceTypeId]
    ├── instanceType
    └── images[]
ZoneSelect an available zoneId from zones.
Instance typeTypes include CPU, memory, disk, bandwidth, inventory, network billing, monthly and hourly pricing, and traffic fields.
ImageRead an imageId from the selected type's images[].
Pricing fieldsPricing and traffic values are service-defined strings; retain the original values when displaying them.

Always query live resource availability before creating an SSH key or VPS. Do not guess, hard-code, or reuse stale zone, type, or image IDs.

SSH Key API

The SSH Key API lists and creates SSH public keys. Except for the resources endpoint, every VPS request carries these runtime-generated headers and follows the same two-layer signing flow as the Model Inference API.

HeaderPlaceholderDescription
X-ParamsBASE64_ENCODED_WALLET_PARAMSBase64-encoded wallet business-signing parameters
X-NonceRANDOM_NONCEA fresh random string for every request
X-SignatureECDSA_SIGNATURE_HEXASN.1/DER signature of SHA-256(X-Params + X-Nonce), hex encoded
X-Public-KeyECDSA_PUBLIC_KEYLocal ECDSA public key used for server verification

The wallet signing message is exactly wallet_address + money + money_id. Base64 encode the complete JSON containing wallet_address, money, money_id, and the wallet signature to form X-Params. Persist the interface key pair securely; regenerate only the nonce and interface signature on each request.

Never write a real private key, complete wallet signature, complete X-Params, X-Signature, X-Public-Key, or management token to source code, repositories, logs, or this documentation. All examples use unusable placeholders.

List SSH keys

curl "https://api-bitgo.enigmhaven.com/vps/v1/ssh-keys" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY"

The response contains sshKeys[], including sshKeyId, displayName, description, publicKey, createdAt, and updatedAt.

Create an SSH key

FieldTypeRequiredDescription
displayNamestringYesDisplay name
descriptionstringYesDescription
publicKeystringYesOpenSSH-formatted public key
curl -X POST "https://api-bitgo.enigmhaven.com/vps/v1/ssh-keys" \
  -H "Content-Type: application/json" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY" \
  -d '{
    "displayName": "dev-key",
    "description": "Development SSH key",
    "publicKey": "ssh-ed25519 PUBLIC_KEY_MATERIAL user@example.com"
  }'
{
  "sshKey": {
    "sshKeyId": "SSH_KEY_ID",
    "displayName": "dev-key",

}

Submit only a public SSH key. Its private key remains securely controlled by its holder and must not be committed or used as bitgo authentication material.

VPS API

Use the VPS API to list, create, inspect, start, stop, and delete instances. Every endpoint uses two-layer signing. Creation, power operations, and deletion change service state, so confirm the target and impact before proceeding.

Endpoint overview

MethodPathDescription
GET/vps/v1/vpsPaginated VPS list
POST/vps/v1/vpsCreate a VPS
GET/vps/v1/vps/{instanceId}Get a VPS
POST/vps/v1/vps/{instanceId}/startStart a VPS
POST/vps/v1/vps/{instanceId}/stopStop a VPS
DELETE/vps/v1/vps/{instanceId}Delete a VPS

List VPS instances

Optional query parameters are pageSize (default 20, maximum 100), pageNumber (starts at 1), and status. The response includes instances, total, pageSize, and pageNumber.

curl "https://api-bitgo.enigmhaven.com/vps/v1/vps?pageSize=20&pageNumber=1&status=InstanceStatusRunning" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY"

Get a VPS

GET /vps/v1/vps/{instanceId} returns an instance object with identification, zone, type, CPU, memory, image, status, creation and expiry times, public and private IPs, NICs, disks, and associated keyId, moneyId, and publicKey.

curl "https://api-bitgo.enigmhaven.com/vps/v1/vps/INSTANCE_ID" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY"

Start a VPS

POST /vps/v1/vps/{instanceId}/start requires an empty JSON object and returns HTTP 200 with an empty JSON object.

curl -X POST "https://api-bitgo.enigmhaven.com/vps/v1/vps/INSTANCE_ID/start" \
  -H "Content-Type: application/json" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY" \
  -d '{}'

Stop a VPS

POST /vps/v1/vps/{instanceId}/stop accepts optional boolean force; the default is a normal shutdown.

curl -X POST "https://api-bitgo.enigmhaven.com/vps/v1/vps/INSTANCE_ID/stop" \
  -H "Content-Type: application/json" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY" \
  -d '{"force": false}'

Use {"force": true} only when normal shutdown fails: it may cause loss of unsaved data.

Delete a VPS

DELETE /vps/v1/vps/{instanceId} returns HTTP 200 with an empty JSON object when successful.

curl -X DELETE "https://api-bitgo.enigmhaven.com/vps/v1/vps/INSTANCE_ID" \
  -H "X-Params: BASE64_ENCODED_WALLET_PARAMS" \
  -H "X-Nonce: RANDOM_NONCE" \
  -H "X-Signature: ECDSA_SIGNATURE_HEX" \
  -H "X-Public-Key: ECDSA_PUBLIC_KEY"

Deletion is normally irreversible. Verify the instanceId, back up data, and obtain explicit authorization first.

Query instance billing summary

GET /vps/v1/billings returns paginated cumulative billing records for VPS instances and can filter by instance ID. This endpoint requires the four headers used for two-layer signing. To verify the latest bitgo wallet balance and VPS consumption details, use the bitgo wallet information and wallet consumption-records query endpoints.

Recommended flow

  1. Query resources and confirm zoneId, instanceTypeId, and imageId.
  2. List or create an SSH Key with two-layer signing.
  3. Create the VPS and retain its returned instanceId.
  4. Poll the single-instance endpoint until the instance is available; do not treat a creation response alone as proof of readiness.
  5. Start, stop, or delete only under explicit authorization.

Error handling and audit

  • The service definition only declares successful 200 responses; always check the actual HTTP status code.
  • Implement finite backoff retries for network timeouts, TLS errors, and 5xx responses. Be careful retrying create, power, and delete operations to avoid duplicate execution.
  • Logs may retain request time, path, status, and redacted server errors. Never log passwords, private keys, or complete authentication headers.
  • Use curl -k only for temporary development connectivity diagnosis when a local certificate trust issue exists; production must validate a valid certificate.
