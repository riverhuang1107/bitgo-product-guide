Reasoning API Call

The agent or software writes task context into messages, selects a model, and sends the request to the reasoning API. The reasoning API supports both the Anthropic Messages and OpenAI Chat Completions protocols. Both protocols use the same signature-authentication headers, but they use different request endpoints, maximum-output-token parameters, and response content fields.

ItemValueDescription
Anthropic Messages endpointhttps://api-bitgo.enigmhaven.com/v1/messagesUse max_tokens and read model output from the response content field
OpenAI Chat Completions endpointhttps://api-bitgo.enigmhaven.com/v1/chat/completionsUse max_completion_tokens and read model output from the response choices[].message.content field
methodPOSTSend a JSON request body
Content-Typeapplication/jsonAlways use JSON
X-ParamsBASE64_ENCODED_WALLET_PARAMSWallet business-signature authentication parameter
X-NonceRANDOM_NONCERandom string used in the interface-level ECDSA signature
X-SignatureECDSA_SIGNATURE_HEXASN.1/DER hex signature over X-Params + X-Nonce
X-Public-KeyECDSA_PUBLIC_KEYLocal ECDSA public key used by the server for verification

usage field notes

  • The actual prices for input_token_unit_price and output_token_unit_price are the field values multiplied by 10^-5. Unit prices are expressed per 1,000 tokens.
  • The actual consumption amount for consume_amount is the field value multiplied by 10^-8.
  • The actual balance for balance is the field value multiplied by 10^-8.
  • If the server response does not include usage, the CLI should output "usage": null and should not estimate or fabricate values.

Models and Pricing

Select a model through the model field in the request body. For the main flow, choose common models by quality, latency, and cost; the full pricing table is in the appendix.

Low costopenai/gpt-5-nano and deepseek/deepseek-v4-flash are suitable for batch classification, summaries, and lightweight decisions.
High qualityclaude-4.6-opus and anthropic/claude-4.8-opus are suitable for complex reasoning, long-form analysis, and high-quality generation.
Code / complex reasoningopenai/gpt-5.2-codex and openai/gpt-5.3-codex are suitable for software development, code review, and engineering tasks.
Fast responseclaude-4.5-haiku and minimax/minimax-m2.5-highspeed are suitable for interactive agents and low-latency business flows.

Security Notes

  • Do not write real private keys, complete X-Params, complete X-Signature, X-Public-Key, or management tokens into repositories.
  • Chain type, deposit network, and amount must be confirmed by a human; money_id is generated automatically by the agent and should not be manually requested from the user.
  • Private keys should be injected through environment variables, a secret manager, or the deployment platform, and should not appear in config templates.
  • Before depositing, verify the official receiving address and mainnet. Transfers to a wrong address or wrong network cannot be automatically recovered by the agent or software.
  • When software calls the reasoning API, record usage, but do not log sensitive headers or private-key material.
  • Example nonce, signatures, balances, hashes, and token counts change with each call and should not be hard-coded into business logic.

Field dictionary

FieldDescription
wallet_chainChain type. Current values are eth, ltc, or btc.
wallet_addressOn-chain address used as the key ID for the user and wallet record.
moneyHuman-confirmed amount or denomination.
money_idAgent-generated amount record or wallet record ID, with a format such as money_20260707_a8f3c91b2e4d. Generating a new random money_id means creating a new bitgo wallet.
signatureBase64 string produced by signing wallet_address + money + money_id.
X-ParamsHeader value produced by base64-encoding the wallet parameter JSON.
X-NonceRandom string used in the interface-level signature.
X-SignatureStrictly concatenate X-Params + X-Nonce in that order and calculate its SHA-256 digest. Use a local ECDSA private key with ecdsa.SignASN1 to generate ASN.1/DER signature bytes over the digest, then hex-encode the result.
X-Public-KeyLocal ECDSA public key used by the server for verification.
usageServer-returned token usage, unit prices, consumption amount, balance, and hash.
